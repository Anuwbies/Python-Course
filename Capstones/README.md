## Working on a project

Read its requirements, accepted inputs, and expected behavior. Implement your own saved files, try the documented ordinary and boundary cases, and ask the assistant for a review. Source, tests, and configuration should demonstrate actual operations rather than print claims of success.

Use the [environment guide](../Courses/Environment_And_Run_Guide.md) for dependencies and run conventions. Database/API tests and CI examples are part of learning software testing, not automatic course-grading tools. External deployment evidence and hardware-dependent measurements have explicit limits in their briefs.

Record reviewed work in [Progress](../Progress/README.md). Reading or running a reference does not complete a student submission.
