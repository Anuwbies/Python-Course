## Updating a record

Use `Not started`, `Reading`, `Practicing`, `Needs revision`, or `Reviewed` for available lessons. Reading a lesson is different from completing its practice and review. Mark the read/practice boxes as those activities happen; mark the review box only after the assistant has reviewed the student's actual saved work and explanation.

When asking for review, identify the lesson or capstone and its saved file. The assistant should inspect the submission, run suitable manual examples, explain strengths and mistakes, and record the result in the corresponding progress file as part of the review. A successful review should include a small change or explanation showing the student understands the code.

For each review, record the date, item, submission path, outcome, and topics needing revision. Do not invent historical dates or infer mastery from opening a file. A supplied reference run is not a student submission. Existing knowledge can be demonstrated through a reviewed task instead of being automatically imported from the old course.

Use a level's retention section at a later study session to revisit a concept without the solution. Keep notes about what was remembered and what needed help. Advancement requires reviewed lesson work and the level capstone, rather than a fixed-question quiz.

## How the records begin

All new lesson and capstone records start unassessed. The old progress labels were not carried into the newly defined curriculum. Each level record links to its available lessons, saved tasks, and capstone. All student statuses remain unassessed until actual work is reviewed.
